# design-spec.md · rh-uni 界面三方向初稿的共同输入

> Phase 3 产物。三版**只看这一份 spec**，各按一套逻辑独立做，互不参考。
> 2026-09-08

## 1. 产品是什么

`rh-uni` 是一个自用的**集中流动性做市（LP）驾驶舱**，跑在 Robinhood Chain 和
BNB Smart Chain 上，操作 Uniswap v4 / PancakeSwap Infinity / Uniswap v3 三个协议。

它干三件事，全都直接动真钱：
1. **进场** —— 输入代币地址 + 预算，工具自动换币、找池或建池、按选定形状（Spot /
   Curve / Bid-Ask）在一笔交易里铺出流动性
2. **监控** —— 盯池价，跳出区间自动撤退
3. **撤退 / 领取** —— 撤本金、领手续费，可选顺手卖成计价币

## 2. 目标受众与使用场景

**受众就是作者本人一个人。** 不需要 onboarding、不需要营销、不需要解释「什么是
流动性」。这一条排除了 90% 的常规 dashboard 设计套路。

真实使用场景有三个，密度需求完全不同：

- **场景 A｜建仓（进场页）** —— 坐着，慢，要看清每个参数。表单十几个字段，
  改一个参数要能立刻看到区间示意图变化。这里可以奢侈。
- **场景 B｜盯盘（仓位页）** —— 站着扫一眼手机/副屏，只想知道**亏没亏、要不要撤**。
  这里必须极密，关键数字要能在 1 秒内被抓住。
- **场景 C｜复盘（日历页）** —— 月度盈亏日历，看哪天赚哪天亏。这是纯数据阅读。

**一个界面要同时服务这三种密度**，是本次设计的核心难题。

## 3. 核心信息与内容板块（全部是线上真实文案，逐字照抄，不许改写）

### 页头
- 品牌位：`rh-uni`
- 链切换：`Robinhood Chain` / `BNB Smart Chain`
- 四个 tab：`进场` `仓位` `盈亏日历` `任务`
- 钱包地址片

### 进场页（左表单 + 右结果）
分组标题：`协议与代币` `池子` `区间` `滑点` `执行后`
关键字段：`协议` `代币地址` `预算（USDG）` `池选择` `费率（%）` `tick 间距`
`最大偏离（%）` `区间写法` `区间（%）` `形状` `层数` `示意图` `换币滑点（%）`
`LP 余量（%）` `继续监控`
形状三选项原文：
- `Spot：一个仓位，区间内均匀`
- `Curve：同心嵌套，越靠现价越厚`
- `Bid-Ask：两侧分段，越远越厚`
主按钮：`计划（演练，不发交易）` → 结果卡片 `换币` `池子` `仓位` `钱包`
→ 危险按钮 `执行这个计划`

### 仓位页
5 张统计卡（标签 + 副标题都是原文）：
| 标签 | 副标题原文 |
|---|---|
| 投入价值 | 每笔存入按当时的池价折算 |
| 现金价值 | 本金 $X + 未领手续费 $Y |
| 手续费收益 | 已领 $X + 未领 $Y |
| 总盈亏 | 现金价值 + 已领手续费 − 投入价值 |
| DPR 日收益率 | 加权持仓 Nd · 其中手续费 X%/天 |

表格列：`仓位` `区间（USDG/代币）` `投入` `价值` `手续费` `uPNL` `DPR` `操作`
行内操作：`领取` `撤退` `监控`；工具条：`重新扫描链上仓位` `刷新价格`
`领取全部手续费` `自动刷新` `卖币走（best / uniswap / okx）` `只撤仓位，不卖币`

### 日历页
5 张统计卡：`本月盈亏` `平仓` `胜率` `最好一天` `最差一天`
月历网格，周一起始，`周一…周日`；有平仓的日子显示当日盈亏，绿涨红跌

### 任务页
表格列：`# 任务 类型 状态 仓位 开始 时长`，下方黑底实时日志

## 4. 情感基调与气质关键词

**冷静 · 可信 · 一眼看到关键数字 · 危险操作有重量感。**

参照物是**彭博终端、券商交易端、飞机 PFD**，不是 Stripe 官网。
用户打开它的典型时刻是「钱已经在池子里了，想知道亏没亏」——所以任何
「欢迎回来 👋」式的亲和都是噪音，任何拖慢读数的装饰都是负资产。

反过来：`执行这个计划` 和 `撤退` 是**不可逆的真实交易**，这两个按钮必须
在视觉上重、慢、需要确认，不能和 `刷新价格` 长一个样。**现有界面这一点做得
不够**——是三版都要解决的共同问题。

## 5. 输出格式与尺寸（三版必须统一，否则无法横向对比）

- **单文件 HTML + 纯 CSS**，双击可开，`file://` 直出，无构建
- **截图视口统一 1440×900**
- 只做**仓位页**这一屏（场景 B，密度最难、信息最全、最能分辨设计好坏）
  + 页头 + tab。进场页/日历页等选定方向后再铺
- 交互可以是死的（静态视觉稿），但不许留空占位

## 6. 已知约束

- 底色沿用现有暖灰 `#f7f6f2`／近黑 `#191918`／赤陶橙 `#d97757`（见 brand-spec）
  —— **例外**：某一版可以整体转暗场，但 accent 不许换成非品牌色
- 盈亏红绿不许动：涨 `#417a5b`，跌 `#c6534f`
- 协议 / 链 logo 必须用官方原件 base64 内嵌（见 brand-spec 资产清单）
- 数字列必须 `tabular-nums`，地址/哈希必须等宽字体
- 中文正文 ≥14px，标签 ≥12px，对比度 ≥4.5:1（skill 硬底线，任何风格不豁免）
- ❌ 禁紫渐变、禁 emoji 图标、禁「深蓝底 + 霓虹 glow」的 GitHub-dark 偷懒解

## 7. 图片需求（Phase 3.5 判定结果）

**内容必需的图 = 协议与链的官方 logo，已全部取到**（Uniswap 独角兽 /
PancakeSwap 兔子 / BNB 金立方 / USDG）。理由：用户每天在两条链三个协议之间切，
**切错协议等于钱进错池子**，图形标记是功能而非装饰，通过"真图诚实性测试"。

除此之外**不需要任何配图**——这是工具型界面，加 stock 图就是 slop。

⚠️ **数据说明**：三版里的持仓数字是**演示数据**，界面上有明确标注。
真实持仓在 `positions.json`（私有，不入稿）。**标签、列名、副标题全部是线上原文**，
只有数值是演示值。

## 8. 视觉母题假设（form 的种子）

这个内容独有、别的主题不会有的视觉元素：**「区间」**。

集中流动性的本质是「你在一段价格区间里放钱，价格走出这段区间你就停止赚钱」。
所以整个产品的母题是**一条带上下界的数轴，和一个在上面移动的当前价标记**。
现有界面里已有雏形（`.rangebar` 那个 120px 的小条），但它被当成一个不起眼的
表格单元格，**没有被当成母题来经营**。

三版各自要回答：**如何让「区间」成为界面的结构性语言，而不只是一个小部件。**
写不出「form 来自内容的哪里」的版本 = 在套模板，作废重做。
